# Esteban UI/UX 기획서 (앱 우선)

> 목표: 기능 붙이기 전에 **모든 페이지의 화면 구조·상태·컴포넌트를 먼저 확정**한다.
> 테마: **Court Energy** (다크 애슬레틱 + 코트 오렌지/일렉트릭 블루/볼트 라임, 볼드 디스플레이 타이포).
> 우선순위: 모바일(앱) 레이아웃이 기준, 데스크톱은 반응형으로 확장.

---

## 0. 디자인 원칙
1. **역동적·명료**: 강한 헤딩, 넉넉한 여백, 한 화면에 하나의 주행동(primary action).
2. **엄지 도달성**: 주요 액션은 하단(탭바/버튼)에, 파괴적 액션은 상단 or 확인 모달.
3. **상태를 항상 설계**: 모든 목록/상세/폼은 `로딩 / 비어있음 / 에러 / 정상` 4상태를 가진다.
4. **일관된 셸**: 모든 화면은 공통 App Shell(상단 앱바 + 콘텐츠 + 하단 탭) 위에 놓인다.
5. **토큰 기반**: 색/간격/타이포는 `_variables.scss` 토큰만 사용(하드코딩 금지).

## 1. 정보구조(IA) & 내비게이션
**하단 탭(1차 내비, 5개)** — 이미 구현됨
`홈` · `라커룸` · `팀원모집` · `경기모집` · `코트대관`

**상단 앱바(맥락)**
- 홈/탭 루트: 로고 + 언어토글 + 프로필/로그인
- 하위 화면: `← 뒤로` + 화면 타이틀 + (선택) 액션 아이콘

**라커룸 2차 내비(세그먼트/스크롤 탭)**
`홈 · 랭킹 · 기록 · 일정 · 게시판 · 팀관리(권한)`

**계층도**
```
홈 /

라커룸 /locker-room
  ├ 랭킹 /rankings
  ├ 기록 /records  → 작성 /records/create
  ├ 일정 /schedule
  ├ 게시판 /team-board
  └ 팀관리 /management → 회비 /management/dues
팀원모집 /recruit      → 작성 /create · 수정 /edit/:id · 상세 /:id
경기모집 /match-board  → 작성 /create · 수정 /edit/:id · 상세 /:id
코트대관 /court-board  → 작성 /create · 수정 /edit/:id · 상세 /:id
404 *
```

## 2. 공통 화면 패턴(템플릿)
설계·구현을 재사용하기 위해 페이지를 4개 템플릿으로 수렴시킨다.

### T1. 리스트 페이지 (모집/경기/코트/기록/게시판)
- 상단: 타이틀 + 검색바 + 필터 칩(상태/지역/날짜)
- 본문: 카드 리스트(썸네일/상태뱃지/메타), 무한스크롤 or 페이지네이션
- 우하단: **FAB(＋ 작성)** — 권한/로그인 시 노출
- 상태: 로딩(스켈레톤 카드) / 비어있음(일러스트+CTA) / 에러(재시도)

### T2. 상세 페이지
- 히어로 헤더(타이틀·상태·핵심 메타·작성자)
- 본문 섹션(설명·조건·위치/지도·참가자)
- 하단 고정 액션바(신청/참가/수정·삭제[작성자])
- 상태: 로딩 / 없음(404 유도) / 권한없음

### T3. 폼 페이지 (작성/수정)
- 섹션형 입력(그룹 라벨), 인풋 하단 헬퍼/에러
- 이미지 업로드(드롭/미리보기)
- 하단 고정 제출바(작성/수정), 이탈 시 확인
- 상태: 검증에러 / 제출중(버튼 로딩) / 성공(토스트+이동)

### T4. 대시보드 페이지 (라커룸 홈/팀관리)
- 요약 스탯 카드(그리드), 바로가기, 최근활동 리스트

## 5. 진행 순서 (기획 → 구현)
1. **디자인 토큰 확정** ✅ (Court Energy 적용됨) — 필요시 미세조정
2. **공통 컴포넌트 키트 구축**(4장) + App Shell(AppBar/콘텐츠/탭)
3. **템플릿 4종 확정**(리스트/상세/폼/대시보드) — 더미데이터로 시각 확정
4. **페이지 스킨 적용**: 홈 → 로그인/프로필 → 라커룸 → 3개 게시판(목록·상세·폼) → 관리/회비 → 404
5. 각 페이지 **4상태(로딩/빈/에러/정상)** 목업 확정
6. 기획 확정 후 **기능(API) 연동** 단계로 전환

각 단계는 더미 데이터로 화면부터 확정하고, 마지막에 기능을 붙인다.

## 6. 미해결/결정 필요
- 기록 작성(스탯 입력)은 데이터량이 많아 **모바일 간이 입력 + 데스크톱 상세 입력** 병행 여부.
- 지도(경기/코트) 제공사(카카오맵 등) 선정.
- 캘린더 UI 라이브러리 vs 커스텀.
- 다크모드 전면 적용 여부(현재는 라이트 콘텐츠 + 다크 크롬).

## 부록: 홈 화면 확정 설계 (2026-07-27)
**성격**: 하이브리드 — 상단은 "우리 팀 대시보드", 하단은 "둘러보기".
**상단바**: 알림 벨 🔔(로그인 시) 추가. (`components/home/NotificationBell.jsx`, 현재 스텁)

**상태별 렌더 (`HomePage.jsx`)**
- 비로그인: 에너지 히어로 슬라이더 + "지금 시작하기" CTA.
- 로그인·팀 없음: 인사 + "팀 만들기/찾기" 카드 + 둘러보기.
- 로그인·팀 있음: 인사 → (멀티팀) 팀 전환 칩 → **다음 경기 참석 투표 카드(센터피스)** → 상태 요약(최근경기/회비/공지) → 둘러보기(모집·경기·코트 진입).

**핵심 결정**
- 재방문 유저 최우선 정보 = **다음 경기 일정 + 참석 투표**(홈 최상단 카드, 참석/불참 버튼 + 현황 바).
- 멀티팀 전환을 홈에서 지원(팀 칩).
- 배너 슬라이더는 로그인 대시보드에선 제외(더미 소스뿐), 비로그인만 유지.

**API 연동 예정(현재 더미)**: 다음 경기(+attendance 투표), 최근 경기 결과, 회비 상태, 팀 공지, 둘러보기 카운트, 알림 목록. 팀 목록은 `myInfo.teams` 사용(리더팀+멤버팀 통합 API로 개선 예정).

## 부록: 도메인/IA 재설계 (2026-08-07 확정)

### 최종 IA
- **홈 탭 제거** → 로그인 후 **우리 팀**으로 바로 진입 (`/` → `/locker-room` 리다이렉트)
- **라커룸 → "우리 팀"** 리네이밍
- **팀원모집 도메인 제거** (게스트 매치가 곧 가입 퍼널이라 불필요)
- **하단탭**: `우리 팀 · 매치 · 코트 · 내 정보`
- 로그인 필수 하드월(비로그인은 로그인 화면만)

### 가입(정회원) 플로우 = 게스트 매치 퍼널
- 농구 동호회는 **게스트로 뛰어보고 → 서로 확인 → 정회원 전환**이 표준
- 그래서 "팀원모집" 대신 **매치**가 유입 경로. 팀 매치 글에 **"정회원 가입 가능" 배지**
- **정회원 모집 정보는 팀(teams) 단위**: `is_recruiting`, `monthly_fee`(nullable=추후안내), `requires_uniform`, `recruit_notice`(안내 문구)

### 매치 종류 (2가지, 완전 별개 개념)
| 종류 | 주최 | 팀 연결 | 정회원 |
|---|---|---|---|
| **팀 매치** | 등록된 동호회 팀 | `team_id`(FK) | ✅ 배지+정보 |
| **픽업** | 개인/체육관 | 없음 | ❌ 일회성 |
- `match_boards.type`: `team` | `pickup` (기존 'guest'는 팀 매치로 흡수)
- 픽업: `host_name`(+선택 `host_type` 체육관/개인) 표기. team_id 없음
- **User ↔ 팀 멤버십** 과 **User ↔ 매치 작성**은 완전 분리 (한 유저가 팀 소속이면서 픽업도 개설 가능)

### 체육관(Gym/Venue) — Phase 2 (아주 나중)
- 돈이 오가는데 개인이 실제 대관했는지 검증 불가 → **트러스트 이슈**
- Phase 2에서 **Gym 1급 엔티티 + 담당자 인증 + 월 타임테이블**(대관 슬롯/픽업 시간) 도입
  → 코트대관 + 픽업이 Gym 중심으로 통합
- **v1은 인증 없음**: 코트/픽업은 정보·연락처 게시만, **인앱 결제·개인 픽업 개방은 Phase 3**

### 개발 우선순위 (확정)
- **Phase 1 (지금) = 코어**: 팀 대시보드(우리 팀 홈) → 회원 관리 → 기록/랭킹(스탯) + 팀 매치(정회원 퍼널)
- **Phase 2 (아주 나중)**: Gym 엔티티 + 인증 + 타임테이블
- **Phase 3**: 인앱 결제/에스크로, 개인 픽업 개방
